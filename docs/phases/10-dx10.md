# Phase 10: DX10 Support

**Status:** TODO
**Depends on:** Phase 5 (DX9 MVP working)

## Goal

Extend DLAA support to DX10 games. Simpler than DX9 because DX10 uses DXGI
for swapchain (existing hooks partially cover it) and has a more structured
constant buffer model.

## What to do

### New name vectors

`DllNames.h`:
```
DEFINE_NAME_VECTORS(dx10, "d3d10", "d3d10_1");
```

### Wrapped device

Create `wrapped/wrapped_d3d10_device.h/.cpp` — wrap `ID3D10Device` / `ID3D10Device1`.
Fewer methods than DX9 (~90 vs 134).

### Jitter injection

DX10 uses constant buffers (`ID3D10Buffer`) instead of `SetTransform`.
Hook `VSSetConstantBuffers` or `UpdateSubresource` to modify the projection matrix.
Similar to Phase 7 (shader constant jitter) but with structured buffers.

### Resource bridge

DX10 surfaces can be opened directly in DX11 via `OpenSharedResource`.
Then use the existing `IFeature_Dx11wDx12` bridge to DX12.
Simpler than DX9→DX12 because DX10 and DX11 share the DXGI resource model.

### Reuse from DX9

- MV compute shader (Phase 4) — same algorithm
- Depth capture logic — similar, but DX10 has cleaner depth surface access
- Upscaler execution — same DX12 backends

## Key differences from DX9

| Aspect | DX9 | DX10 |
|--------|-----|------|
| Swapchain | Own `Present()` | DXGI (existing hooks help) |
| Matrices | `SetTransform` (fixed-function) | Constant buffers only |
| Depth access | `GetRenderTargetData` | Cleaner via DXGI shared resources |
| Resource sharing | D3D9Ex shared handles | DXGI shared handles (native) |
| Compute shaders | None | Limited (SM 4.0) |

## Verification

- Test with a DX10 game (e.g., Halo 3 ODST, Lost Planet 2)
- Same quality expectations as DX9 DLAA
